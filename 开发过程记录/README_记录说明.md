# 开发过程记录 · 说明

本文件夹用于保存「诊后助手」项目的开发与修改过程，便于改错回溯、版本比对、里程碑留存。

## 文件约定

| 文件 | 作用 | 维护方式 |
|---|---|---|
| `README_记录说明.md` | 本说明（固定入口） | 几乎不变 |
| `项目执行记录_索引.md` | 全貌索引：决策、对象定义、文件清单、版本对照 | 阶段性更新，内容可改写 |
| `开发日志.md` | 按日流水：每次改动的时间、原因、改动点、如何回溯 | **只追加，不覆盖** |

## 维护规则（后续每次改项目时执行）

1. 动手前先看 `项目执行记录_索引.md` 确认当前版本与红线。
2. 每次完成实质性改动后，在 `开发日志.md` **末尾追加**一条记录，格式统一：

   ```
   ### YYYY-MM-DD HH:MM 标题
   - 改动前状态 / 触发原因
   - 改了什么（具体到文件、模块、字段）
   - 如何回溯（对应 git commit 号，或上一版本文件路径）
   - 已知遗留 / 待办
   ```

3. 涉及方向性决策（对象定义、模块边界、视觉基调、红线条款）时，同步更新 `项目执行记录_索引.md`。
4. 改动都走 git commit；记录里务必带上 commit 号，方便 `git checkout` 精确回退。

## 配套回退手段（与本记录互补）

- **git**：项目已纳入版本管理（main 分支）。回退单文件用 `git checkout <commit> -- <path>`，整体回退用 `git checkout <commit>`。
- **版本化新稿**：涉及 `.docx` 原文件，遵循「永不覆盖原始 Word，改动用版本化新稿」的既有约定（见索引）。
- **工作区记忆**：`~/.workbuddy/.../2026-11-02-09-16-32/.workbuddy/memory/` 下的日志是另一份时间线，可交叉参照。
